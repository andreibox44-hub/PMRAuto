# PMRAuto

## Что это за сайт

PMRAuto — площадка объявлений о продаже транспорта для Приднестровья (ПМР) и Молдовы.
Пользователи смотрят каталог, ищут машины по фильтрам, регистрируются, размещают свои
объявления и переписываются с продавцами.

- Сайт: https://andreibox44-hub.github.io/PMRAuto/ (GitHub Pages, публикуется из ветки `main`;
  после `git push` обновляется через минуту-другую, браузер может держать старую версию
  до 10 минут — Ctrl+F5).
- Код: https://github.com/andreibox44-hub/PMRAuto (ветка `main`, remote `origin`).

## Файлы

- **`index.html`** (~315 КБ, ~5860 строк) — весь сайт: разметка, CSS и JavaScript.
  **Важно:** первая строка файла сразу закрывает `<head>`. Метатеги (title, description,
  Open Graph, иконки) стоят внутри неё перед `</head>` — новые теги для `<head>` добавлять туда.
- **`catalog.js`** — справочник марок и моделей (`window.VEHICLE_CATALOG`), подключён перед
  основным скриптом.
- **`supabase/schema.sql`** — полная схема базы с нуля; **`supabase/update.sql`** — короткое
  обновление со всеми изменениями после первой версии. Оба можно запускать повторно
  (Supabase → SQL Editor → New query → Run), данные не трогаются.
- `img/` — фото баннера `hero.jpg`; `favicon.svg`, `favicon-32.png`,
  `apple-touch-icon.png`, `og-image.png` (превью для соцсетей, 1200×630).

## На чём сделан

- **Чистый HTML + CSS + JavaScript** без фреймворков и сборщиков. Своего сервера нет.
- **Бэкенд — Supabase** (проект `pguqsuamvakmoejnqhze`, https://pguqsuamvakmoejnqhze.supabase.co).
  Библиотека `supabase-js@2.58.0` с jsdelivr с `integrity`. В начале скрипта — `SUPABASE_URL`
  и публичный ключ `SUPABASE_KEY` (publishable, его можно держать в коде; **секретный ключ
  в код не вставлять**). В Supabase: пользователи (Auth, вход по e-mail и паролю), профили,
  объявления, чаты, сообщения, фото (Storage, папка `photos/<id пользователя>/…`).
- **Схема базы**: таблицы `profiles`, `listings`, `chats`, `messages`, правила доступа (RLS),
  функции `username_taken`, `my_chats`, `mark_chat_read`, `delete_my_account`,
  `schema_version`. Менять схему через SQL можно только в панели Supabase (у публичного
  ключа нет прав) — готовить SQL и просить владельца запустить его.
- **Версия схемы** — функция `schema_version()`, **сейчас 4** (база обновлена 17.10.2026).
  Сайт читает её при загрузке в `db.schema` (нет функции — 1). Возможности по версии:
  3 — год выпуска с 1930, колонка `doors`, пять коробок передач; 4 — дополнительные
  характеристики и комплектация. Пока база старее, форма эти поля не показывает
  (`sellYears()`, `sellTransmissions()`, `extraFieldsHtml()`), чтобы сохранение не ломалось.
  **Меняя схему:** дописать изменения в `schema.sql` и `update.sql`, увеличить число в
  `schema_version()`, в коде проверять `db.schema >= N`, дать владельцу SQL для запуска.
- Телефон из профиля — личный: хранится в `user_metadata.phone`, а не в общей таблице
  `profiles` (её видят все). Телефон в объявлении — публичный (`listings.phone`).
- Подтверждение e-mail в Supabase **выключено** (встроенная почта Supabase шлёт всего
  несколько писем в час); код умеет работать и с включённым.
- В `localStorage` — только язык, валюта, курс, избранное, сравнение, время последнего вопроса
  (`const KEYS`) и сессия Supabase. Ключи старой версии (`OLD_KEYS`) удаляются при запуске.
- **Фото баннера** указано путём `img/...` в `HERO_PHOTO`; `photoSrc()` берёт
  картинку из `window.EMBEDDED_PHOTOS`, если её туда встроили. Пути относительные: роутер
  меняет только часть адреса после `#`. Если роутер начнёт менять сам путь — пути поправить.
- Фото объявлений кэшируются CDN Supabase (`cacheControl: 3600`): удалённое фото может
  ещё недолго открываться по старой ссылке.
- **Валюта:** цены в базе (`listings.price`) — **в евро**. На экран — в валюте из шапки
  (EUR/USD, `currency`, `am_currency`); пересчитанная цена с «≈», цена в евро — в `title`
  (`fmtPrice()` возвращает разметку, `fmtMoney()`/`fmtEuro()` — текст). Курс — раз в сутки с
  `api.frankfurter.dev/v1` (бывший frankfurter.app, курс ЕЦБ), хранится в `am_rate`; нет ответа —
  последний сохранённый, совсем нет — `RATE_FALLBACK`. Фильтр цены в поиске — в выбранной
  валюте (сравнение с `shownPrice()`), в адресе при этом `cur=USD`; без `cur` цена в ссылке —
  в евро. При смене валюты фильтр пересчитывается. В форме подачи рядом с ценой — валюта
  (`priceCurrency`), при сохранении пересчёт в евро (`sellPriceEur()`); при редактировании
  цена показывается в евро.
- **Шрифт** Onest из Google Fonts. **Форма «Задать вопрос»** отправляет письма через
  Web3Forms (`WEB3FORMS_ACCESS_KEY` в начале скрипта).
- Цвета — CSS-переменные в `:root`, есть тёмная тема (`prefers-color-scheme: dark`).

### Устройство кода

- **Роутер:** `go(name, param)` и `router()`. У каждой страницы свой адрес через решётку
  (работает на GitHub Pages без настроек):
  `#/` главная · `#/search?brand=BMW&…` поиск (в адресе только фильтры, отличные от
  `DEFAULT_FILTERS`) · `#/car/<id>` объявление · `#/sell`, `#/sell/<id>` подача и
  редактирование · `#/account/<вкладка>`, `#/account/messages/<id чата>` кабинет и чат ·
  `#/user/<логин>` страница продавца · `#/page/<id>` · `#/favorites` · `#/compare`
  (`my` — старый адрес, ведёт на `#/account/listings`).
  Перевод туда-обратно — `routeToHash()` / `hashToRoute()`, запись в историю — `setHistory()`.
  Адрес — источник правды: при загрузке (`boot`) и на «Назад» (`popstate`) страница берётся
  из него. Ссылкам `[data-go]` настоящий `href` подставляется при наведении (`linkHash`),
  поэтому работают «Открыть в новой вкладке» и Ctrl+клик.
- Служебные адреса Supabase из писем (`#access_token=…`, `#error=…`) — не маршруты:
  открывается главная, адрес приводится к `#/`. Ссылку с ошибкой убираем ещё до запуска
  Supabase, иначе он выходит из аккаунта.
- Страницы только для вошедших (`requireLogin()`) после входа открывают ту страницу, куда шли.
- Каждая страница рисуется функцией `view*()` (`viewHome`, `viewSearch`, `viewDetail`,
  `viewSell`, `viewAccount`, `viewUser`, `viewPage`, `viewFavorites`, `viewCompare`)
  в `<main id="app">`.
- **Данные с сервера** загружаются при запуске (`boot()` → `loadData()`) и лежат в памяти
  в объекте `db` (`db.listings`, `db.users`, `db.me`, `db.schema`), поэтому страницы
  рисуются без ожидания. `refreshData()` обновляет их не чаще раза в 30 с при переходах;
  если объявления или продавца нет в памяти (свежая ссылка), `refetchMissing()` один раз
  перезагружает данные, и только потом показывается «не найдено».
- Внутри кода пользователи — это **логины** (`owner`, `buyer`, `seller`); id из базы нужны
  только для запросов (`listing.ownerId`, `db.me.id`, `nameOf(id)`). Колонки базы
  (`engine_volume`) переводятся в поля объявления (`engineVolume`) в `listingFromRow()`.
- **Чаты** — через `chatApi` (запросы к Supabase), новые сообщения приходят сразу через
  Supabase Realtime (`subscribeMessages`).
- **Тексты** — в объекте `I18N` (`ru`/`en`), вывод через `t('ключ')`, склонения — `plural()`.
  **Любой новый текст нужно добавлять в оба языка.**
- **Значения с вариантами хранятся кодами**, на экран выводятся переводом:
  топливо `FUELS`, коробка `TRANSMISSIONS` (manual, automatic, cvt, robot, semiauto),
  кузов `BODIES`, цвет `COLORS` (показ — `colorLabel()`; у старых объявлений
  цвет текстом), двери `DOORS`, привод `DRIVES`, места `SEATS`, состояние `CONDITIONS`,
  экокласс `ECO_CLASSES`, цвет салона `INTERIOR_COLORS`, материал `MATERIALS`,
  комплектация `FEATURES` (12 кодов, колонка `features text[]`). Старые русские значения
  переводятся через `LEGACY_VALUES`. Годы — `YEAR_OPTIONS` (текущий → 1930, `MIN_YEAR`).
- **Справочник марок и моделей (`catalog.js`):** для `car`, `moto`, `truck`, `van` —
  `popular` (популярные марки по порядку, первые 12 — плитки на главной) и `models`
  (марка → модели примерно с 2000 года; 177 марок, ~1600 моделей). Модели — семействами
  (BMW «3 Series», Mercedes «C-Class»); `resolveModel()` относит к ним «320d», «C 200 4MATIC».
  В списках марок сверху «Популярные марки», потом «Все марки», в конце «Другая» (`OTHER`) —
  при ней появляется поле для ручного ввода. Сортировка — `byName` (по алфавиту, числа по
  значению). Своя марка/модель из объявлений попадает в списки поиска автоматически.
  Русские названия и другие написания марок — `BRAND_RU`, `BRAND_ALIASES`.
- **Форма подачи и редактирования** — одна (`viewSell(id)`, `editingId`):
  марка/модель — `setSellBrandModel()`, `updateSellModels()`, `readSellBrandModel()`;
  дополнительные поля и галочки — `extraFieldsHtml()`, `setFeatureChecks()`; заполнение при
  редактировании — `fillSellForm()`; цена, пробег, мощность, объём — только цифры
  (`data-digits`), расход — цифры и одна запятая (`data-decimal`). При смене языка
  введённое (включая фото и галочки) сохраняется — см. `setLang()`.
- **Поиск:** `searchFieldsHtml()`, `bindSearchForm()`, «Другая» в поиске — `searchOther`,
  сброс — `resetFilters()`, совпадение — `matches()`.
- **Примеров объявлений нет** (удалены 17.10.2026 вместе с фото): на сайте только объявления
  из базы (`getListings()` = `db.listings`). Когда их нет совсем, на главной и в поиске —
  «Пока нет объявлений» и «Продать авто» (`noListingsHtml()`).
- В шапке кнопки подачи нет: форму открывают «Продать авто» на главной (баннер и пустой
  список) и «+ Добавить машину» в кабинете («Мои объявления»: маленькая кнопка над списком,
  без объявлений — по центру с текстом «У вас пока нет объявлений»).
- Комментарии в коде — на русском.

## Как проверять

- Локально: `python -m http.server 8765` в папке проекта + Edge
  `C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe --headless=new
  --remote-debugging-port=9333 --user-data-dir=<временная папка>`, управлять через DevTools
  Protocol из Node (встроенный WebSocket). Для двух пользователей одновременно — отдельные
  контексты браузера (`Target.createBrowserContext`).
- Тесты работают с **настоящей базой**: тестовые аккаунты — `pmrauto.test+<что-то>@gmail.com`,
  в конце теста удалять их через сайт («Удалить аккаунт»). **Аккаунт `andreibuilds` —
  настоящий (владелец), его не трогать.** После проверки убедиться, что в базе не осталось
  тестовых профилей и объявлений.
- **В базе есть настоящие объявления владельца** (с 17.10.2026 — Ford C-Max от `andreibuilds`):
  тесты не должны рассчитывать на пустую базу или удалять чужие объявления. Пустое состояние
  («Пока нет объявлений») проверять, подменив `db.listings = []` в странице.
- Скрипты тестов лежат во временной папке сессии и не сохраняются — в новой сессии писать заново
  (маленький клиент DevTools Protocol: контекст браузера на страницу, `Runtime.evaluate`,
  `Page.captureScreenshot`; переход между адресами одной страницы — через `about:blank`, иначе
  смена только `#` страницу не перезагружает).
- Подтверждение e-mail должно быть выключено, иначе Supabase будет слать письма на тестовые
  адреса (отказы портят репутацию проекта).
- Проверять и на живом сайте: те же тесты с адресом https://andreibox44-hub.github.io/PMRAuto/.
